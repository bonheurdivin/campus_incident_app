# Campus Incident Reporter

A Flutter mobile app that lets students report campus issues (broken facilities, water or electricity outages, sanitation and safety concerns) and lets authorized campus staff review reports and update their status until they are fully resolved.

Built using Flutter, Provider, Firebase Authentication, Cloud Firestore and Cloudinary (for image hosting).


## Features

**Students**
- Register and sign in only with an ALU email address (`@alustudent.com` or `@alueducation.com`)
- Email verification required before the account starts functioning
- Submit an incident with category, title, description, location and an optional photo
- Browse all reports, search by text, and filter by status and category
- View report details with a live status timeline
- Edit or delete their own report while it is still "Submitted"
- Home screen with a personal summary (My Reports, Submitted, In Progress, Resolved)

**Campus staff**
- Staff dashboard with totals and a "Needs attention" list
- Update an incident's status (Submitted, In Progress, Resolved) with an optional note shown in the timeline
- Delete reports (for example spam or duplicates)

## Project structure

```
lib/
  main.dart                  App entry, providers, AuthGate
  firebase_options.dart      Generated by flutterfire configure
  core/                      validators.dart, format.dart
  models/                    enums.dart, app_user.dart, incident.dart, status_entry.dart
  services/                  auth_service.dart, incident_service.dart, storage_service.dart
  providers/                 auth_provider.dart, incident_provider.dart
  screens/
    auth/                    login, register, verify email
    home/                    student home
    report/                  report form (create and edit)
    reports/                 list with search and filters
    details/                 incident details, timeline, staff actions
    staff/                   staff dashboard
    profile/                 profile and sign out
    main_shell.dart          bottom navigation
  widgets/                   incident_card, status_chip, summary_tile, page_header
firestore.rules              Firestore security rules
```

**Layering:** UI (screens and widgets) reads state from Providers. Providers call Services. Services are the only code that talks to Firebase or Cloudinary. Models convert between Dart objects and Firestore documents.

## Getting started

### Prerequisites
- Flutter SDK installed (`flutter doctor` shows no blocking issues)
- Android Studio with an emulator, or a physical device
- A Firebase account and a free Cloudinary account
- Node.js, then `npm install -g firebase-tools` and `dart pub global activate flutterfire_cli`

### 1. Clone and install
```bash
git clone https://github.com/bonheurdivin/campus_incident_app.git
cd campus_incident_app
flutter pub get
```

### 2. Firebase setup
1. Create a project in the [Firebase Console](https://console.firebase.google.com).
2. **Authentication**: enable the Email/Password provider.
3. **Firestore Database**: create a database.
4. **Rules**: copy the contents of `firestore.rules` into Firestore, Rules, and publish.
5. Connect the app to your project (this regenerates `lib/firebase_options.dart`):
```bash
firebase login
flutterfire configure
```

### 3. Cloudinary setup (photo uploads)
1. Create a free account at cloudinary.com and note your **Cloud name**.
2. Go to Settings, Upload, Upload presets, Add upload preset. Set **Signing mode: Unsigned**, asset folder `incident_photos`, and turn on **Disallow public ID**.
3. Open `lib/services/storage_service.dart` and set:
```dart
static const _cloudName = 'your-cloud-name';
static const _uploadPreset = 'your-preset-name';
```

### 4. Run
```bash
flutter run
```

## Roles and creating a staff account

- Everyone who registers is given a **student** access.
- To make a staff account: register and verify the account, then open **Firebase Console, Firestore, users, (the user's document)** and change the `role` field from `student` to `staff`, Sign out and then sign back in.

## Firestore data model

```
users/{uid}
  name, email, role ("student" | "staff"), createdAt

incidents/{incidentId}
  title, description, location,
  category  ("facilities" | "water" | "electricity" | "safety" | "sanitation"),
  status    ("submitted" | "inProgress" | "resolved"),
  imageUrl (nullable), reporterId, reporterName, createdAt, updatedAt

incidents/{incidentId}/statusHistory/{entryId}
  status, changedBy, note, timestamp
```

## Security summary (`firestore.rules`)

- Only signed-in users with a **verified ALU email** can read incidents.
- Students can create reports only as themselves, always with status `submitted`.
- Students can edit or delete their own report only while it is `submitted`.
- **Only staff** can change `status`, and the rule limits staff updates to the `status` and `updatedAt` fields.
- Staff-only status history entries; history is never updated after creation.
- All other access is denied by default.

## Limitations

- Cloudinary uses an unsigned preset, so anyone who learns the preset name could upload files to the account. A production version would use signed uploads from a backend.
- Staff accounts are set manually in the Firebase Console. A production version would use an admin tool or Firebase custom claims.
- Reports are visible to all verified saff members (to support browsing). A future version could add anonymous reporting for sensitive safety issues.
- Push notifications for status changes are not implemented.
